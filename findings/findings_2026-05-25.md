## 1) ICS Threshold Mechanics

### 1.1 What the 9 ICS levels mean

The detection phase produces nine ICS archives regardless of any setting. Each archive
corresponds to a correlation threshold applied to the per-sample R² (or Pearson r)
values from the linear regression detection:

| Level (archive name) | Correlation threshold | Selectivity |
|---------------------|----------------------|-------------|
| 090 → `ics_original_090.zip` | r > 0.09 | **Strictest** — fewest ICS, highest-quality samples |
| 080 | r > 0.08 | |
| … | … | |
| 010 → `ics_original_010.zip` | r > 0.01 | **Most permissive** — most ICS, lowest quality cutoff |

`SHA3_TRAINING_ICS_LEVEL` (default: 10) selects which archive flows into training.
All nine archives are always present in the sandbox after detection completes.
Re-running training at a different level costs nothing on the detection side.

Validation rule (`check_ics_archive.py --max-empty 0`): **every** intermediate value
word must have at least one ICS sample. A single word with an empty array causes the
pipeline to die with "ICS archive validation failed."

**Important:** `run_overnight_chain.sh --with-training` does NOT call check_ics_archive.py.
If training is restarted manually with this script, an invalid (empty-array) archive can
silently pass through, corrupting the templates for affected words.

### 1.2 Cross-scale ICS level history

| Experiment | ICS level used | How set |
|-----------|---------------|---------|
| All smoke v2 sigma sweeps (hd/hw/id/f9, all σ) | **10** (r > 0.01) | global_config.py default; env files did not override |
| Midscale v1 σ=0.1–2.5, all modes | **90** (r > 0.09) | Explicitly set in midscale env files |
| Midscale v1 f9 σ=3.0–4.0 | **50** (r > 0.05) | Fixed in-place after pipeline failure at level 90 |
| Midscale v1 hd/hw/id σ=3.0–4.0 | **90** | Passed validation; run was not adjusted |

**Comparability implication:** Smoke and midscale results are NOT on the same ICS basis.
Smoke used the most permissive threshold (level 10); midscale used the strictest (90) for
most runs. Within each scale, results are internally consistent.

For the thesis, smoke results are a qualitative pilot; midscale/paperscale are the
quantitative comparison. Do not cross-reference specific SR numbers between smoke
and midscale without acknowledging the ICS level difference.

## 2) Midscale f9 ICS Boundary Map

All 9 ICS archives exist in every midscale sandbox (detection is complete for all 36 runs).
The following table shows the **highest level that passes `check_ics_archive.py`** for each
sigma × mode combination, measured empirically from the midscale archives (30 det sets):

| Sigma | f9 max valid level | hd/hw/id max valid level |
|-------|-------------------|-------------------------|
| 0.1–2.5 | **90** | **90** |
| 3.0 | **70** (level 80 fails: 6 empty arrays) | **90** |
| 3.5 | **50** (level 60 fails: 4 empty arrays) | **90** |
| 4.0 | **40** (level 50 fails: 9 empty arrays) | **90** |

The f9 mode degrades faster than hd/hw/id because its per-bit leakage is weaker (random
coefficient model with bit_coeff_scale=1.0 → lower expected SNR per sample). hd/hw/id
retain sufficient correlation at level 90 across all tested sigma values.

**Why paperscale may allow higher levels:** More detection traces (100 det sets vs 30
midscale) → stronger R² signal → more samples exceed any given threshold. After paperscale
detection completes, verify whether f9 σ=3.0–4.0 can use levels 70–90 before
hardcoding the training ICS level.

## 3) Midscale Data Quality Issue: f9 σ=4.0

The midscale f9 σ=4.0 run was restarted at ICS level 50 using `run_overnight_chain.sh
--with-training`. Because this script bypasses `check_ics_archive.py`, the run completed
silently with **9 empty ICS arrays** — 9 intermediate value words had no samples above
the r > 0.05 threshold.

**Effect:** The template profiling for those 9 words used zero useful training windows.
The resulting LDA models are trained on noise only. Subsequent SASCA beliefs for those
words are effectively random, reducing attack success.

**Required fix (before archiving f9 σ=4.0):** Re-run training at level 40 (the highest
valid level for this run). The ics_original_040.zip archive passes validation with 0 empty
arrays. Steps:
1. Update sandbox `.env`: set ICS level and all four tags to 40/040.
2. Clean 0003_training subdirectory outputs.
3. Restart via `run_overnight_chain.sh --with-training`.
4. Verify with `check_ics_archive.py --ics-zip ics_original_040.zip` (should show OK).

## 4) Per-Sigma ICS Level Standard

For comparability across modes at the same noise level, all four modes should use the
same ICS level at a given sigma. The standard uses the **highest level that passes for
all modes** (i.e., the f9 bottleneck determines the level):

| Sigma | Standardized ICS level | Rationale |
|-------|----------------------|-----------|
| 0.1–2.5 | **90** | All modes pass; maximum selectivity |
| 3.0 | **70** | f9 fails at 80 (6 empty); hd/hw/id unaffected |
| 3.5 | **50** | f9 fails at 60 (4 empty); hd/hw/id unaffected |
| 4.0 | **40** | f9 fails at 50 (9 empty); hd/hw/id unaffected |

Thesis argument: *"We used the highest R² correlation threshold that produced non-empty
ICS for all four leakage modes at each noise level, balancing template selectivity against
the available signal strength."*

**Current midscale discrepancies** (require training re-runs, detection is preserved):
- f9 σ=4.0: must re-run at level 40 (currently broken at level 50)
- f9 σ=3.0: optionally re-run at level 70 (currently 50; 70 is the standard)
- hd/hw/id σ=3.0: optionally re-run at level 70 (currently 90; mismatch with f9)
- hd/hw/id σ=3.5: optionally re-run at level 50 (currently 90; mismatch)
- hd/hw/id σ=4.0: optionally re-run at level 40 (currently 90; mismatch)

Only f9 σ=4.0 is mandatory. All others are recommended for cross-mode comparability
at the σ=3.0–4.0 sigma slices.

## 5) Correction to findings_2026-05-21.md §3.3

**§3.3 claim:** "The pipeline selects samples with correlation r > 0.09" and "the ICS
selection threshold is not crossed until σ≈6."

**Correction:** The smoke runs used ICS level 10 (r > 0.01), not level 90 (r > 0.09).
With r > 0.01, the ID cutoff sigma is:

```
r_ID(σ) = sqrt(0.25 / (0.25 + σ²)) = 0.01
→ σ_cutoff = sqrt(0.25/0.0001 − 0.25) ≈ 50
```

The ID mode retains all ICS points until σ≈50, far beyond any tested sigma value.
The observation (ID is noise-insensitive across σ=0.1–4.0) is correct; the stated
threshold (r > 0.09, σ_cutoff ≈ 5.5) was the level 90 value, not the level 10 value
actually used by the smoke runs.

**Updated analysis for midscale (level 90, r > 0.09):**
At r > 0.09, the ID cutoff is:
```
r_ID(σ) = sqrt(0.25 / (0.25 + σ²)) = 0.09
→ 0.25/(0.25 + σ²) = 0.0081 → σ² = 30.6 → σ ≈ 5.5
```
So for midscale with level 90, ID ICS also survives the entire σ=0.1–4.0 range (confirmed
empirically: all midscale id runs passed at level 90). The §3.3 calculation applies
correctly to midscale, not to smoke.

**Implication:** If the purpose is to observe ID noise-sensitivity, even midscale with
level 90 will show flat performance until σ≈5.5. A sweep extending to σ=6–8, or a
deliberate switch to a lower ICS level (e.g. level 70, cutoff σ≈3.7), would be needed
to see ID degradation in the noise range of interest.
